# Урок для сайта

Работай из корня репозитория по AGENTS.md. Прочитай incoming/README.md и website/lessons/README.md; остальную историю запрашивай только при нехватке конкретного условия или согласования.

## Если составляешь листок в другом чате

Подготовь incoming/<id>/lesson.tex, lesson.json и нужные figures/ по incoming/_template/. Используй формат сайта, не печатную преамбулу. Сохрани порядок и разделение задач/ДЗ; ограничения методов возьми из поручения. Все решения проверь математически. Неизвестное содержание или спорное исправление вынеси в unresolved_questions, оставив draft. Подготовка комплекта не подразумевает изменение графа или публикацию.

## Если добавляешь урок

1. Проверь git status и актуальность origin/main. Сохрани пользовательские правки. Найди точный комплект, проверь его редакцию и ограничения; status=ready — заявление о готовности, а не доказательство правильности и не разрешение на публикацию.
2. Сам запусти `python3 website/scripts/add-lesson.py incoming/<id>`. Проверь математические решения и полноту материалов. Отсутствующие данные уточняй, не придумывай. Затем сам запусти ту же команду с `--apply`, если установка новых исходников входит в задачу. Скрипт не меняет реестр/граф и не перезаписывает существующие уроки.
3. Размещение определяет пользователь. Без указания продолжения маршрута/компонента уточни только это, выполнив независимую подготовку. Не добавляй вершины/связи по умолчанию и не меняй общую раскладку. Когда размещение задано, внеси нужные изменения в website/data/topics.json вручную. Сейчас валидатор поддерживает один последовательный маршрут; отдельная компонента требует согласованной реализации при реальной необходимости. Не пытайся обойти проверку фиктивным ребром.
4. Не добавляй в новый урок ссылки на всю предыдущую теорию: эта особенность пока принадлежит только существующей «Практике решения задач».
5. Собери сайт и запусти test-authoring.py, test-add-lesson.py, verify-site.py из website/scripts/. Проверь страницу, карту, формулы, ссылки и открытие разборов соразмерно изменению. Общие тесты не проверяют математическую истинность новых решений.
6. Если публикация авторизована, закоммить только связанные изменения, отправь main, дождись успешной GitHub Actions публикации. При недоступном CLI используй подключённый GitHub с expected_sha; после такой публикации синхронизируй корневую рабочую копию с origin/main, не затирая чужие изменения. Входные комплекты не включай в коммит без необходимости.
7. В ответе дай ссылку на урок, краткую проверку и реальные нерешённые вопросы. Не пересобирай архивы для обычного урока.
